# 이관 가이드 — 다른 프로젝트에 붙이기

이 템플릿을 실제 서비스 프로젝트에 옮겨 붙일 때 읽는 문서다.
무엇을 복사하고, 어디에 두고, 무엇을 고치고, 무엇을 건드리면 안 되는지를 순서대로 적었다.

읽는 사람은 이 템플릿을 받아 화면을 만들 퍼블리셔와 개발자다.
프레임워크는 가리지 않는다. 정적 HTML·CSS·JavaScript라 정적 파일을 서비스할 수만 있으면 어디든 붙는다.

기능 명세와 화면 구성은 [README.md](README.md)에 있다. 이 문서는 옮기는 일만 다룬다.

---

## 1. 먼저 정할 것

템플릿 네 가지 중 하나를 고른다. 섞어 쓰지 않는다. 한 서비스 안에서 두 가지를 같이 쓰면
글자 크기 조절과 고대비가 페이지마다 다른 방식으로 동작해 이용자가 혼란스러워진다.

| 파일 | 이름 | KRDS | 고르는 기준 |
|---|---|---|---|
| `pages/main.html` | 표준 포털형 | 준수 | 무난하고 심사에 안전하다. 정할 근거가 마땅치 않으면 이것. |
| `pages/main-b.html` | 큰글씨 안내형 | 준수 | 이용자가 절차를 따라오게 해야 할 때. 신청 흐름이 중심인 서비스. |
| `pages/main-c.html` | 자립형 | 미준수 | KRDS 준수 의무가 없고, 따뜻하고 친근한 인상을 만들어야 할 때. |
| `pages/main-d.html` | 몰입형 | 미준수 | KRDS 준수 의무가 없고, 정제되고 현대적인 인상을 만들어야 할 때. |

**KRDS 준수 여부를 먼저 확인한다.** 정부·공공 웹 서비스 구축 사업은 발주 요건에
KRDS 적용이 들어 있는 경우가 많다. 그런 사업이라면 자립형과 몰입형은 선택지가 아니다.
요건서에 근거가 없으면 발주처에 확인하고 결정한다.

고른 뒤 나머지 두 개의 페이지와 전용 CSS는 지워도 된다.

## 2. 옮기는 절차

### 2.1 복사할 파일

고른 템플릿에 따라 복사할 양이 다르다.

**표준 포털형을 고른 경우**

```
css/senior.css
js/senior.js
vendor/krds/          (통째로)
pages/main.html
```

**큰글씨 안내형을 고른 경우**

위와 같고 `css/main-b.css`와 `pages/main-b.html`을 더 가져간다.

**자립형을 고른 경우**

```
css/standalone.css
js/standalone.js
vendor/krds/fonts/    (글꼴만. 나머지 KRDS 자산은 쓰지 않는다)
pages/main-c.html
```

**몰입형을 고른 경우**

```
css/immersive.css
js/immersive.js
vendor/krds/fonts/    (글꼴만. 나머지 KRDS 자산은 쓰지 않는다)
pages/main-d.html
```

검증 스크립트 `checks/check.mjs`는 어느 쪽이든 함께 가져가면 옮긴 프로젝트에서도 쓴다.

용량은 다음과 같다.

| 묶음 | 용량 |
|---|---|
| KRDS 자산 전체 (`vendor/krds/`) | 3.7MB |
| 그중 글꼴 6개 | 1.8MB |
| 그중 디버깅용 지도 파일 3개 | 816KB |
| 그중 통합 스타일 한 장 | 570KB |
| 그중 이미지 95개 | 366KB |
| 그중 스크립트 한 장 | 94KB |

**운영 배포에서는 절반 가까이 덜어낼 수 있다.**

- 글꼴의 구형 형식(`.woff`) 세 개를 빼면 약 1MB 줄어든다.
  크롬, 엣지, 사파리, 파이어폭스는 신형(`.woff2`)만으로 충분하다.
  인터넷 익스플로러를 아직 지원해야 하는 기관이면 남겨 둔다
- 지도 파일(`.map`) 세 개를 빼면 816KB 줄어든다.
  원래 스타일 원본을 브라우저 개발자 도구에서 되짚어 보라고 딸려 오는 파일인데,
  그 원본을 이 템플릿은 가져오지 않으므로 쓸 데가 없다.
  세 개 중 둘은 이미 지워진 스타일을 가리키는 빈 참조다.
  지울 때 통합 스타일 맨 끝의 지도 파일 참조 주석도 함께 지운다. 안 지우면 개발자 도구에 경고가 뜬다

둘 다 빼면 전송량이 약 1.8MB로 줄어든다.
어느 쪽이든 실제 전송은 서버 압축이 걸리면 훨씬 작아진다. 스타일과 스크립트에 압축을 켜 둔다.

### 2.2 정적 폴더에 배치

프로젝트의 정적 파일 폴더 아래에 **폴더 구조를 그대로 유지한 채** 넣는다.

```
<정적 루트>/
  css/
    senior.css
    main-b.css        (큰글씨 안내형을 쓸 때만)
    standalone.css    (자립형을 쓸 때만)
    immersive.css     (몰입형을 쓸 때만)
  js/
    senior.js
    standalone.js
    immersive.js
  vendor/
    krds/
      css/
      js/
      fonts/
      img/
```

스택별 정적 루트는 다음과 같다.

| 스택 | 정적 루트 | 웹에서 보이는 경로 |
|---|---|---|
| 스프링 부트, JSP, 타임리프 | `src/main/resources/static/` | `/css/senior.css` |
| 리액트, 뷰 (Vite, CRA) | `public/` | `/css/senior.css` |
| 넥스트, 넉스트 | `public/` | `/css/senior.css` |
| 아파치, 엔진엑스 정적 사이트 | 문서 루트 | `/css/senior.css` |

복사 명령 예시다. 경로만 프로젝트에 맞게 바꾼다.

PowerShell

```powershell
$src = "C:\workspace\yeonjae\krds-senior-templates"
$dst = "C:\내프로젝트\src\main\resources\static"
Copy-Item "$src\css"    $dst -Recurse -Force
Copy-Item "$src\js"     $dst -Recurse -Force
Copy-Item "$src\vendor" $dst -Recurse -Force
```

bash

```bash
SRC=~/krds-senior-templates
DST=~/내프로젝트/src/main/resources/static
cp -r "$SRC/css" "$SRC/js" "$SRC/vendor" "$DST/"
```

### 2.3 페이지에 링크 걸기

**표준 포털형과 큰글씨 안내형**은 머리말에 스타일, 몸말 끝에 스크립트를 넣는다.

```html
<head>
  <link rel="stylesheet" href="/vendor/krds/css/token/krds_tokens.css">
  <link rel="stylesheet" href="/vendor/krds/css/component/output.css">
  <link rel="stylesheet" href="/css/senior.css">
  <!-- 큰글씨 안내형이면 아래 한 줄 더 -->
  <link rel="stylesheet" href="/css/main-b.css">
</head>
<body>
  ...
  <script src="/vendor/krds/js/krds.js"></script>
  <script src="/js/senior.js"></script>
</body>
```

**자립형과 몰입형**은 두 줄이 전부이고 스크립트가 머리말에 들어간다.

```html
<head>
  <!-- 자립형 -->
  <link rel="stylesheet" href="/css/standalone.css">
  <script src="/js/standalone.js"></script>

  <!-- 몰입형 -->
  <link rel="stylesheet" href="/css/immersive.css">
  <script src="/js/immersive.js"></script>
</head>
```

이 스크립트에 `defer`나 `async`를 붙이면 안 된다. 이유는 3.2에 있다.

### 2.4 마크업 옮기기

페이지 파일의 `<body>` 안을 통째로 가져간 뒤, 머리말과 꼬리말을 잘라 공통 조각으로 만든다.

- 스프링, JSP, 타임리프는 인클루드 조각으로 나눈다
- 리액트, 뷰는 컴포넌트로 나눈다

리액트나 뷰로 옮길 때 마크업에서 바꿀 것은 속성 이름뿐이다.

| HTML | 리액트 |
|---|---|
| `class` | `className` |
| `for` | `htmlFor` |
| `tabindex` | `tabIndex` |
| `aria-*`, `data-*` | 그대로 |

뷰는 그대로 써도 된다.

### 2.5 자리표시자 바꾸기

페이지 안의 기관명, 연락처, 링크는 전부 예시값이다. 옮긴 뒤 반드시 실제 값으로 바꾼다.

| 자리표시자 | 무엇 | 페이지 4종 합계 |
|---|---|---|
| `○○기관` | 기관명 | 23곳 |
| `1234-5678` | 대표전화 | 18곳 |
| `(00000) ○○시 ○○구 ○○로 00` | 주소 | 4곳 |
| `href="#"` | 이동할 주소 | 표준형 29곳, 큰글씨형 26곳, 자립형 27곳, 몰입형 34곳 |
| `PET-20260919-0012` | 접수번호 예시 | 큰글씨형 1곳 |
| `2026.09.18` 등 | 새소식 날짜 | 10곳 |
| `2026년 9월 23일 수요일` | 자립형 안내 카드의 날짜 | 서버에서 오늘 날짜로 넣을 것 |
| `홍길동`, `010-0000-0000` | 몰입형 첫 화면 그림 속 예시값 | 보여 주기용이라 그대로 둬도 된다 |
| `favicon.svg` | 파비콘 | KRDS 기본값이다. 기관 것으로 바꾼다 |

로고도 지금은 글자다. 기관 로고 이미지가 나오면 바꾼다.
표준형과 큰글씨 안내형은 `.snr-logo-text`, 자립형과 몰입형은 `.brand` 안이다.
이미지로 바꿀 때 대체 텍스트에 기관명을 반드시 넣는다.

## 3. 주의점

### 3.1 폴더 구조를 바꾸면 깨지는 것

파일들은 서로를 상대 경로로 찾는다. 배치를 바꾸면 다음이 깨진다.

| 무엇을 옮기면 | 무엇이 깨지나 | 고치는 곳 |
|---|---|---|
| `vendor/krds/` 안을 재배치 | 아이콘이 전부 안 보임 | 고치지 말고 구조를 되돌린다 |
| `css/`와 `vendor/`를 떼어 놓음 | 글꼴만 안 나옴 | `senior.css` 또는 `standalone.css` 맨 위 글꼴 선언의 경로 |

`vendor/krds/`는 KRDS 원본이다. 안쪽 구조를 유지해야 하는 이유는 두 가지다.

- 통합 스타일이 아이콘을 두 단계 위로 올라가 찾는다. `css/`와 `img/`가 나란히 있어야 한다
- 통합 스타일이 토큰 파일을 따로 불러온다. `css/component/`와 `css/token/`이 나란히 있어야 한다

### 3.2 순서를 바꾸면 깨지는 것

**스타일 순서.** 토큰, 통합, 고령층 순으로 넣는다. 고령층 스타일이 마지막이어야 한다.
순서가 바뀌면 글자가 KRDS 기본값인 17px로 돌아가고 터치 영역도 작아진다.
큰글씨 안내형의 전용 스타일은 그보다도 뒤다.

**스크립트 순서.** KRDS 다음에 고령층 스크립트다.
바뀌면 글자 크기 선택값이 새로고침 뒤에 복원되지 않는다.

**자립형·몰입형 스크립트 위치.** 머리말에 넣고 지연 로딩을 붙이지 않는다.
첫 화면이 그려지기 전에 저장된 글자 크기와 고대비를 적용해야 화면이 번쩍이지 않는다.
몸말 끝으로 내리거나 `defer`를 붙이면 밝은 화면이 잠깐 보였다가 어두워진다.

### 3.3 KRDS 원본을 고치지 말 것

`vendor/krds/` 안의 파일은 손대지 않는다. 바꿀 것은 전부 고령층 스타일에서 덮어쓴다.
원본을 고치면 KRDS 버전을 올릴 때 수정분이 통째로 사라진다.

배포판 중 `krds.min.css`는 쓰지 않는다. 아이콘 주소가 `krds.go.kr` 절대 경로라
인터넷이 막힌 내부망에서 아이콘이 전부 깨진다.
이 템플릿이 쓰는 통합 스타일은 상대 경로판이라 내부망에서도 동작한다.

### 3.4 마크업을 옮길 때 자리를 지켜야 하는 것

표준 포털형과 큰글씨 안내형에는 위치가 중요한 자리가 있다.
조각으로 나눌 때 무심코 옮기면 동작이 깨진다.

- **모바일 전체메뉴는 `<header>` 바로 아래, 헤더 안쪽 묶음의 바깥에 둔다.**
  헤더 안쪽 묶음에는 KRDS가 변형 속성을 걸어 두어서, 그 안에 넣으면 화면 전체를 덮어야 할 메뉴가
  헤더 높이만큼만 열린다. 이 자리에 주석을 남겨 두었다
- **글자 크기 항목마다 빈 숨김 요소가 하나씩 있어야 한다.** KRDS 스크립트가 여기에 "선택됨"을 써넣어
  화면 낭독기에 현재 선택을 알린다. 비어 있다고 지우면 안 된다
- **몰입형도 전체메뉴를 길잡이 띠 바깥에 둔다.** 띠에 뒤가 비치는 효과가 걸려 있어
  그 안에 넣으면 화면 전체를 덮지 못한다. 원인은 다르지만 증상은 KRDS 쪽과 같다
- **메뉴 열기 버튼과 닫기 버튼의 표시 속성을 지운다면 동작이 끊긴다.**
  KRDS는 열기를 특정 한 곳, 닫기를 특정 한 곳에만 연결한다.
  하단 고정 바의 버튼과 아래쪽 큰 닫기 버튼은 고령층 스크립트가 그 한 곳을 대신 눌러 준다

### 3.5 낮추면 안 되는 값

이 템플릿의 존재 이유다. 디자인을 손보더라도 아래는 유지한다.

| 항목 | 값 | 근거 |
|---|---|---|
| 본문 글자 | 20px 이상 | 시력 저하 대응. KRDS 기본값 17px를 올려 둔 것이다 |
| 터치·클릭 영역 | 48px 이상 | 손 떨림 대응 |
| 명암비 | 4.5:1 이상 | 웹 접근성 지침 |
| 포커스 표시 | 3px 실선 + 여백 | 키보드 조작 |
| 정보 전달 | 색 하나로만 전달하지 않기 | 상태는 색과 글자를 함께 쓴다 |

색을 기관 색으로 바꿀 때 명암비를 반드시 다시 잰다.
특히 밝은 하늘색이나 연한 회색 글자는 대부분 기준에 못 미친다.

### 3.6 화면 전환형(SPA)에서 주의할 것

리액트나 뷰로 화면을 갈아 끼우면 머리말이 다시 그려진다.
KRDS 스크립트는 문서가 처음 열릴 때 한 번만 연결되므로, 다시 그려진 머리말에는 아무 동작도 붙지 않는다.
주메뉴가 안 펼쳐지고 글자 크기 드롭다운이 안 열린다.

머리말 컴포넌트가 화면에 붙을 때마다 KRDS 초기화 함수를 다시 부른다.
주메뉴, 모바일 메뉴, 드롭다운, 글자 크기 조절이 최소한이다.

자립형과 몰입형은 이 문제가 없다. 자기 스크립트가 문서 전체에 한 번만 연결되고
버튼은 속성으로 찾기 때문이다.

## 4. 증상과 원인

옮긴 뒤 자주 나오는 증상이다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 글자가 작다 (17px) | 고령층 스타일이 먼저 실려 KRDS에 덮였다 | 스타일 순서를 뒤로 보낸다 |
| 아이콘이 전부 안 보인다 | `vendor/krds/` 안쪽 구조가 바뀌었다 | 구조를 되돌린다 |
| 아이콘이 내부망에서만 안 보인다 | 배포판 `krds.min.css`를 썼다 | 통합 스타일(상대 경로판)로 바꾼다 |
| 글꼴이 기본 고딕으로 나온다 | `css/`와 `vendor/`가 떨어졌다 | 글꼴 선언의 경로를 고친다 |
| 새로고침하면 글자 크기가 원래대로 | 스크립트 순서가 뒤집혔다 | KRDS 다음에 고령층 스크립트 |
| 화면이 밝았다가 어두워진다 | 자립형·몰입형 스크립트를 몸말로 내렸거나 지연 로딩을 붙였다 | 머리말로 올리고 지연 로딩을 뗀다 |
| 전체메뉴가 헤더 높이만큼만 열린다 | 모바일 메뉴를 헤더 안쪽 묶음에 넣었다 | 바깥으로 꺼낸다 |
| 화면 전환 뒤 메뉴가 안 열린다 | 화면 전환형에서 재초기화를 안 했다 | 머리말이 붙을 때 KRDS 초기화를 다시 부른다 |
| 확대하면 가로 스크롤이 생긴다 | 격자 칸에 최소 너비 0이 빠졌다 | 새로 만든 격자 칸에 최소 너비 0을 준다 |
| 낱말이 가운데서 잘린다 | 줄바꿈 설정을 `anywhere`로 바꿨다 | `break-word`로 되돌린다 |

## 5. 서버에서 설정 미리 적용하기

글자 크기와 고대비는 브라우저 저장소에 남아 다음 방문 때 복원된다.
다만 화면이 한 번 그려진 뒤 적용되므로 아주 짧게 번쩍인다.

서버 렌더링을 쓴다면 같은 값을 쿠키에도 저장하고, 서버가 최상위 태그에 속성을 미리 찍으면 번쩍임이 사라진다.

| 템플릿 | 속성 | 값 |
|---|---|---|
| 표준형, 큰글씨형 | `data-krds-mode` | `high-contrast` |
| 자립형, 몰입형 | `data-contrast` | `on` |
| 자립형·몰입형 글자 크기 | `data-text-size` | `lg` 또는 `xlg` |

속성은 최상위 태그에만 붙인다. 다른 곳에 붙이면 적용되지 않는다.

## 6. 검증

검증 스크립트를 함께 가져갔다면 옮긴 프로젝트에서 그대로 쓴다.

```
node checks/check.mjs
```

네 가지를 확인한다.

1. 페이지와 스타일이 가리키는 파일이 실제로 있는지
2. 필수 접근성 마크업(언어 표시, 제목, 건너뛰기 링크)이 있는지
3. 자립형·몰입형 페이지가 KRDS 자산을 끌어오지 않는지
4. KRDS 스타일에 외부 절대 주소가 남지 않았는지

엣지나 크롬이 깔려 있으면 페이지마다 화면 다섯 장, 네 템플릿이니 모두 스무 장을 만든다.
넓은 화면 기본과 고대비, 좁은 화면 기본과 150% 확대와 고대비다.
좁은 화면 그림 위쪽에 가로 넘침 측정값이 찍히므로 확대해도 안 깨지는지 눈으로 확인할 수 있다.

스크립트가 통과해도 다음은 사람이 직접 봐야 한다.

- 키보드 탭만으로 모든 기능을 쓸 수 있는지
- 화면 낭독기로 읽었을 때 순서가 맞는지
- 기관 색으로 바꾼 뒤 명암비가 4.5:1 이상인지
- 실제 휴대전화에서 눌러 봤을 때 손가락으로 정확히 눌리는지

## 7. KRDS 버전 올리기

표준 포털형과 큰글씨 안내형만 해당한다. 현재 버전은 `vendor/krds/VERSION`에 적혀 있다.

```
npm pack krds-uiux@<버전>
```

받은 압축을 풀어 아래를 `vendor/krds/`에 덮어쓰고 버전 파일을 갱신한다.

| 원본 안의 위치 | 옮길 곳 |
|---|---|
| `resources/css` | `vendor/krds/css` |
| `resources/fonts` | `vendor/krds/fonts` |
| `resources/img` | `vendor/krds/img` |
| `resources/js/component/ui-script.js` | `vendor/krds/js/krds.js` |

가져오지 않는 것이 있다. 슬라이드 플러그인 스타일과, 통합 스타일에 이미 들어 있는 낱개 스타일들이다.
디버깅용 지도 파일도 필요 없다.

덮어쓴 뒤 검증 스크립트를 돌리고 화면을 눈으로 확인한다.
KRDS가 클래스 이름이나 구조를 바꿨다면 고령층 스타일의 덮어쓰기가 빗나갈 수 있다.
